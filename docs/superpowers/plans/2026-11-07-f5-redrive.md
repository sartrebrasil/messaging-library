# F5 parte 2: redrive — plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ferramenta de redrive (ADR-0012) no core, com bean e endpoint Actuator (desligado por padrão) no starter, verde no contrato dos seis brokers.

**Architecture:** O laço de leitura com condições de fim sai do `DeadLetterPass` para `PassReader` (package-private, `com.example.messaging.inbox`). `DefaultInboxRedrive` (mesmo pacote) o usa sobre a origem e copia para o destino ou para o fim da origem. A API pública fica em `com.example.messaging.inbox.redrive`. O starter monta as rotas por receiver, o bean, um decorador de métricas e o endpoint.

**Tech Stack:** Java 21, Maven, JUnit 5, Spring Boot 4 (Actuator), Micrometer, Testcontainers.

**Spec:** `docs/superpowers/specs/2026-11-07-f5-redrive-design.md`

## Global Constraints

- `limit` 1..10_000; `maxPerSecond` ≥ 1 no core, 100 quando omitido no endpoint.
- Combinações: `FAILED → MAIN`, `FAILED → DEAD_LETTER`, `DEAD_LETTER → MAIN`; demais recusadas.
- Exceções da API: `IllegalArgumentException` (inválido), `NoSuchElementException` (receiver inexistente), `IllegalStateException` (execução em curso) → endpoint 400 / 404 / 409.
- Cópia movida: sem `inbox_failure`, `inbox_attempts=l2=0;l3=0;redrive=<id>`, `deduplicationId` = `messageId` de origem.
- Endpoint com acesso padrão nenhum; ligar exige `access=unrestricted` **e** exposição.
- `DeadLetterPassTest` não muda (prova da extração).
- Branch `feat/f5-redrive`; merge só com pedido.

## Review Focus

1. Mensagens puladas pelo filtro voltando antes das que ainda não foram lidas → a execução termina (`NEWER_THAN_PASS`) mas nunca move uma pulada; o relatório diz por que parou. Teste na Task 2.
2. Receiver de tópico + subscription com `target=MAIN` → recusado antes de ler (não publica para todas as subscriptions). Teste nas Tasks 2 e 3.
3. Duas chamadas simultâneas para o mesmo receiver e origem → a segunda recebe 409 / `IllegalStateException` e a primeira não é afetada. Teste nas Tasks 2 e 4.
4. Endpoint sem as duas chaves → não responde (404 do Actuator), nem com só uma delas. Teste na Task 4.
5. Mensagem sem `inbox_failure` (vinda de fora da inbox) → agrupada como `none`, filtrável por data, movida sem erro. Teste na Task 2.
